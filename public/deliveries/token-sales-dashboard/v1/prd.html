1. 项目概述

产品经理和模型运营使用本看板观察 API 实际用量，先发现消耗变化，再用模型明细定位变化来源。这里把「销量」定义为 Token 使用量，金额、定价与结算口径留待确认。

2. 整体流程

  1. 打开看板，读取默认七天的五项合计。
  2. 选择日期或模型并应用，三个页面区域同步联动。
  3. 切换趋势指标，悬停或键盘聚焦某天的柱条查看精确值。
  4. 在模型表格点击数字列列头排序，定位高用量模型；用「重置」回到初始视图。

3. 页面说明

3.1 筛选与指标

标注 北京时间 2026-11-16 至 2026-11-22，含首尾，默认全部模型。

页面简述 上方选择分析范围，下方展示该范围内的用量合计。

日期与模型

  • 内容 「开始日期」与「结束日期」为必填日期，使用 Asia/Shanghai 的统计日。「模型」为单选下拉，可选全部模型、长文模型 A、通用模型 B、低延迟模型 C、代码模型 D。
  • 交互 编辑筛选值后点击「应用筛选」刷新指标、趋势和明细。「重置」恢复默认筛选、默认趋势和默认排序。
  • 数据来源 示例中每条记录已按日、模型汇总。正式版需统一请求发生时间与归集时区。

核心指标口径

指标类型与单位定义默认示例
输入 Token整数 · Token归一后的输入总量，包含符合该口径的缓存读取及缓存创建所涉及的输入。20,984,171
输出 Token整数 · Token模型实际生成的 Token，按筛选范围合计。3,488,750
缓存命中 Token整数 · Token本次请求从已有缓存读取的输入 Token。14,003,639
缓存创建 Token整数 · Token本次请求用于写入新缓存的输入 Token。1,756,243
调用次数整数 · 次正式版按唯一 request_id 计数。演示读取已聚合的独立请求数。126,499

缓存读写是输入用量的分析维度。计算总 Token 时使用「输入 Token + 输出 Token」，避免把缓存量再次计入。

3.2 用量趋势

标注 默认展示输入 Token。纵轴使用紧凑单位，柱条提示使用完整整数。

页面简述 在相同筛选范围内查看单项指标的日变化。

指标切换

  • 选项 输入 Token、输出 Token、缓存命中 Token、缓存创建 Token、调用次数。
  • 交互 切换后只刷新趋势。悬停或键盘聚焦柱条可查看统计日及精确数值，序列从早到晚排序。
  • 逻辑 按日期对筛选范围内的记录求和，纵轴按当前量级调整。Token 指标单位为 Token，调用次数单位为次。

3.3 模型看板

标注 四个名称均为虚构，正式模型来源于实际目录。

页面简述 对比模型用量，查看哪个模型贡献了最多输入、输出或请求。

明细列与排序

  • 内容 从左到右为模型（文本）、输入 Token、输出 Token、缓存命中 Token、缓存创建 Token、调用次数。五列数值为整数，口径对应图 1，各自按模型聚合。模型名称旁条形表示该模型输入量÷当前筛选范围内的总输入量，悬停可查看百分比。
  • 交互 默认输入 Token 降序。点击新的数字列按该列降序排列，再点击反转。相同数值按模型名称排序。窄屏可滚动，模型列固定在左侧。

4. 状态与异常

情况显示与处理
开始日晚于结束日显示「开始日期不能晚于结束日期」，保留上一组有效结果。
筛选无匹配记录指标显示「—」，趋势和模型区域分别显示无数据，日期和模型选择保留。
数值实际为 0有效的零值显示 0；输入占比分母为 0 时样机条形为空。
上游字段缺失或未归集正式运维需区分缺失、延迟和 0。展示与归集策略待确认。

5. 原型边界

样例内置 7 天 × 4 模型共 28 条虚构聚合记录。生产接入前，需要确认供应商 usage 字段映射、调用成功与失败的归集范围、重试去重和统计延迟。
