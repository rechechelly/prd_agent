# 截图与验收

## 4. 截图规则
截图是文档的主体之一，不是装饰。读者只看图就能认出这是哪个页面、有哪些列。
## 4.1 一张图对一个 h3
* 图片数量必须等于「页面说明」下的 h3 数量。
* 一块界面一张图；同一个弹窗不要拆成两张。
* 同一节的图，视角、宽度、缩放必须一致；两张图背景列对不上，读者会以为这是两个页面。
## 4.2 必须完整
正文提到的每一列、每个按钮，图里都要看得见。最常见的失误是：表格 14 列，截图只截到第 9 列，正文却在讲第 14 列。
稳妥做法：先量表格实际宽度，再把视口设成刚好装下全部列，最后才截。
```javascript
// 在页面里取真实宽度
const wrap = document.querySelector('.table-wrap');
const table = document.querySelector('table');
console.log({ viewport: innerWidth, client: wrap.clientWidth, scroll: table.scrollWidth });
```

* 视口宽度 ≈ 侧栏宽度 + 内容区内边距 + table.scrollWidth + 少许余量。
* 视口高度 ≈ 分页条底部 + 14px，避免大片空白。
* 竖屏窄视口下必须横向滚动才能看全时，就不要截全表：改为截「关键列 + 固定列」的视角，并在红色标注里说明其余列的方位。
## 4.3 裁切与清晰度
* 用 2 倍缩放（deviceScaleFactor: 2）截图，缩到 920px 文档宽度后文字仍清晰。
* 只裁四周多余的白边；不要裁掉顶栏、筛选区或分页条，它们是「这是哪个页面」的证据。
* 裁切以「最后一行有内容的像素」为下边界，不要用固定高度。
* 弹窗图里，标题、正文、两个按钮必须完整，不能被裁掉或压在遮罩边缘。
## 4.4 命名与标注
* 文件名：01-overview.png、02-reset.png，两位序号 + 英文短名。
* alt：一句话说清图里有什么，例如「设备管理列表，时间列四行，最右为设备重制」。
* figcaption：图 1　设备列表。默认查询为全部，示例 5 条，最右列为「操作」。补默认条件和当前选中项。
* 图里没有的控件，正文不能写成已有；图里已经删掉的列，在红色标注里写「本页不提供」。
## 4.5 截完要验
* 图片能加载，宽度大于 0，不是一张白图。
* 缩小到文档实际显示宽度后，表头和按钮文字仍然认得出来。
* 弹窗图里按钮没有被截断。
* 连续两张图并排放时，表头位置、列顺序一致。

## 9. 写完自查
在浏览器里真的点一遍，逐条打勾：
* 目录每个锚点都能跳到对应章节 
* 每张图都能加载，图片数量等于页面说明的 h3 数量 
* 标注是红色 #d83931，图题在图下方居中、13px 灰色 
* 正文提到的每个字段、按钮、弹窗文案，都能在截图或原型里找到 
* 同一节的几张图，表头位置、列顺序一致 
* 全文搜「保持线上」「其余不变」这类笼统说法，逐处改成逐列定义 
* 原型里点「行内操作」，弹窗能开；点「取消」、按 Esc、点遮罩，都能关；「确认」后该行真的变了；提示条出现 
* 刷新原型，数据回到初始示例 
* 窄屏下表格横向滚动，首列固定 
* 页头四行齐全，原型链接能跳回原型 
* 状态表覆盖了：未启用 / 缺字段 / 操作成功 / 操作失败 / 查询无结果 
* 没有编造未见过的枚举值、负责人姓名或真实业务数据

只有适用且已确认的状态需要实现。若失败或空状态文案未知，标为「待确认」，不要为打勾编造业务规则。正式环境行为与原型的模拟能力须明确区分。
