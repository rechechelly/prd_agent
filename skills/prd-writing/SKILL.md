# 产品经理需求文档与原型

设计新产品需求时，交付一份可编辑需求文档和一个可交互 HTML，二者共用字段、状态和示例。仅评审或修改已有文件时按用户指定范围处理。

在叙页工作台的对话中，读取本包的[撰写规范](generation-prompt.txt)。用 `write_online_file` 创建实际的文档正文（document）和单文件原型（html），默认将 parent_id 设为当前在线文件的 ID，使两份交付并列放在其下。长内容先写骨架，再用 `edit_online_file` 分段完善，也可用 Bash 写好源码后通过 `import_task_file_to_workspace` 将草稿导入已创建的目标 ID。按下文验证两个文件。为当前需求增改字段或交互时，优先用 edit_online_file 就地修改当前文件。用户明确指定另一个目标时，再用 list_online_files 定位该文件。需要配图时，使用配套的 data-prd-view 和 data-prd-shot 标记，调用 `embed_view_screenshots` 并检查工具结果。工作台已配置截图浏览器，此步骤直接由工具完成。最终用 `read_online_file` 核对交付内容。

用户提供的截图或文案可能描述旧流程。先区分现状和本次改动，再用一条具体的「初始数据 → 用户操作 → 预期结果」场景验证改动。连续操作涉及累计金额或状态时，覆盖中间状态和最终状态。

## 输入与事实边界

最少确认：页面是什么、给谁用、有哪些字段和操作。优先读取用户提供的现有 HTML、截图、字段清单、角色权限、数据量与已删除功能；会影响核心流程的缺失信息先询问，独立部分继续推进。

未见过的枚举值、按钮、空状态文案、权限和业务规则不得写成已确认需求。非阻塞项标「待确认」；演示数据明确为虚构示例。参考文件里的设备重制等业务仅为例子，不自动继承。

正文用简体中文；英文产品名、字段名和版本号保持原样。前台侧重按钮和提示文案、出现条件与去向；后台侧重逐字段口径、公式、状态迁移和联动范围。同一产品的前台和后台分成两份文档。

## 独立文件交付位置

- `<交付根目录>/<中文页面名>.html`：单文件原型。
- `<交付根目录>/docs/<中文页面名>-需求说明.html`：需求说明。
- `<交付根目录>/docs/assets/<英文小写短名>/01-xxx.png`：截图，序号从 01 连续。

在工作台内，使用已登记的目标路径，PRD 使用文档类型。独立交付的交付根目录遵循用户或当前环境的输出约定，无约定时用项目根目录。中文文件名与页面标题一致。原型完全自包含；文档的样式内联，截图以相对路径引用并一并交付，原型链接为 `../<中文页面名>.html`。移动交付物时保留目录结构。

## 配套交付流程

以下步骤用于新需求的配套交付。

1. **先定数据。** 列明字段、类型、枚举、状态、空值规则与动作结果。按实际界面顺序逐项定义，不用「保持线上」「其余不变」吞掉原有字段。
2. **实现原型。** 读取 [原型规则](references/prototype.md)。核心输入、点击、弹窗及提交后的整行状态变化必须真实可用；刷新恢复初始数据。宽表在容器内滚动且首列固定。已确认且适用的状态以 4～6 行自洽示例覆盖，不为凑状态发明业务枚举。仅作展示的非核心控件集中说明。
3. **实测并截图。** 读取 [截图与验收](references/screenshots-and-qa.md)。先在浏览器走通核心流程，再按文档实际区块截取原型。页面说明下每个 h3 对应一张真实截图。禁止用手绘或生成图替代原型截图。
4. **写需求文档。** 读取 [文档规则](references/document.md)，按需复制 [HTML 骨架](assets/prd-template.html)。页头固定版本、日期、负责人、原型四行，日期用实际文档日期，负责人写「产品经理」。五章依次为项目概述、整体流程、页面说明、状态与异常、原型边界。页面说明每个 h3 按截图及图题、红色标注、页面简述、功能点 h4 的顺序组织；h4 下只使用规定的六类说明标签。需要具体例子时再读 [列表与弹窗示例](references/example.md)。
5. **对照验收。** 按截图与验收参考检查链接、锚点、图片、窄屏与交互；核对字段、按钮、弹窗、示例数字和动作结果在原型、截图、文档中一致。原型行为变更后更新受影响截图及文档。清除模板占位内容，保留明确标注的业务「待确认」项。
6. **交付。** 给出两个 HTML 的位置及打开方式，截图目录随文档交付，说明仍待确认的关键事项。不得把未实测的行为声称为已通过。

若环境无法运行浏览器或获取截图，先完成可做部分并明确指出尚未完成的截图或验证，不伪造截图、不交付带失效图片的文档并称其完成。工具和实现方式按可用能力选择，不绑定外部站点、服务或框架。
